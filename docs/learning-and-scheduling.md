# Learning history and automatic practice

The shared learning view derives records from completed timed Forma sessions and imported Codeforces practice groups. Every record retains its source IDs, problem identities, Codeforces handle, submission IDs and reflection source. It leaves source records untouched. Only timed sessions contribute measured minutes. Imported acceptance is platform activity; until a reflection exists, the outcome remains pending and contributes no independent or assisted learning credit.

The default progress scope contains personal timed sessions and the currently connected Codeforces profile. An archived profile can be selected explicitly. Learning groups use both problem identity and handle, so one profile's assisted attempt cannot become a breakthrough because a different handle later solved that problem. A later independent timed session on the same imported problem can become a breakthrough after an imported assisted or unsolved reflection.

Two records that describe the same attempt can be explicitly linked. A link is one-to-one, must identify the same Codeforces problem and must match the imported handle. Linking uses the chosen timed or imported reflection for one learning credit. Both original reflections, timed notes, elapsed time and submission provenance remain preserved. Unlinking restores their separate credit. Forma never links based on timestamp proximity. Problems without usable platform identities cannot be linked by title.

Difficulty counts come from reflections. Topic practice counts recorded attempts, including pending imported activity; topic coverage does not imply mastery. Topic aliases are normalized in the derived view while original platform tags remain intact. Practice-day consistency counts local calendar days containing a completed timed session or imported submission. It does not infer minutes or independent understanding.

Automatic suggestions exclude future revisit dates, deliberate practice deferrals, recommendations skipped today and archived problems. A problem can still be opened intentionally from Problems. Completing a revisit clears its schedule and records a completion timestamp without claiming a successful attempt. Older reflection edits cannot bring that completed task back; genuinely later practice can propose another revisit. Rescheduling changes its revisit date. Skipping Today only suppresses that day's recommendation. Archiving excludes automatic practice while keeping history. Missing fields in old backups preserve the previous default eligibility.

Schema version 2 remains backward compatible. Missing learning links and discovery preferences receive empty/default values; reminder preferences default to disabled. Version 1 notes, timestamps, active sessions and deliberate revisit dates remain supported. Strict validation rejects broken links, duplicate credit, unknown handles and invalid scheduling dates.

Regression tests cover imported-only metrics, pending-vs-fresh states, cross-source breakthroughs, handle isolation, explicit-link credit, preserved notes/minutes and a 10,000-attempt multi-year history. Those tests assert exact counts and provenance rather than timing thresholds.
