# Integration and usability review fixes

This pass addresses the review of `dfa5595` on 8 October 2026. The checkout was clean at that commit. No major feature, dependency, account migration or deployment was added.

## Reproductions and resulting behavior

1. **Hybrid PDF omission.** The actual Chromium worker imported a PDF containing native `381A` rows and raster `1791C`. It kept two intentional `381A` memberships, omitted `1791C`, and reported no warning. Default extraction now keeps native text/annotations/stages and requires a page-coverage decision when images remain unread. Requested all-page OCR recovers `1791C`; position and identity reconciliation removes overlapping OCR copies while preserving repeated rows at different positions. Disagreements remain source evidence requiring review. Decorative images warn without automatic OCR or engine downloads. See [Track Studio](track-studio.md) for the explicit recovery steps and geometry/English OCR limitations.

2. **Corrected upsolve completion.** A real independent timed upsolve changed to Unsolved previously failed strict validation because its completion reference remained. Reconciliation now checks current canonical identity, actual session relationship, outcome and explicitly selected reflection/profile provenance before validation. An unsupported completion is cleared while its queue addition, original session relationship, date and priority remain; a later solved correction can complete it again. Administrative removal stays removed. Historical contest results remain unchanged; the original attempt ID, timestamps, measured time and notes are preserved while its outcome is corrected. Reconciliation is idempotent and the tests exercise backups, failed writes, retries and recovery.

3. **Shared contest learning.** Contest-only confirmed reflections were absent from shared history, Memory’s latest summary and mistake insights. Today could call those problems untouched and ignore today’s contest when describing a return after a break. Shared queries now project distinct contest participation and confirmed understanding with original contest/problem links. Drafts and self-reported status alone never imply an independent solve. Imported submissions inside a contest window support that contest event once; outside submissions remain separate, and original imported records/reflections remain accessible. Explicit real timed/import links retain their existing selected-source precedence. Native contest reflection takes precedence over an imported reflection in that contest event. No timed attempt or per-problem duration is created.

   Personal, current and archived profile scopes apply to the shared projection. Track progress consumes the same records and keeps independent understanding, platform acceptance and measured time distinct. Return-after-break uses original activity dates, including actual contest starts; changing old reflection text does not become new coding. Automatic expiry uses the original start or last actual supporting submission rather than the unattended deadline as its problem activity date. Existing revision schedules still produce schedule-backed candidates. Genuine imported quick-reflection completion remains valid; a native contest reflection cannot fabricate one.

4. **Lost upsolve priority.** Under equal conditions with fifteen minutes available, the eligible queue put high-priority `4B` first but final planner sorting selected normal-priority `4A`. Explicit priority now travels through coding candidates and saved plan items. Due dates and existing activity/session precedence come first; equal-date upsolves use high before normal, followed by canonical identity and candidate key. Future dates, skips, deferrals, archives and profile boundaries still apply. Changed automatic priorities/order leave visible stale rows and replacement choices; deliberate, started and ended selections remain attached to their original choice. Legacy selections without a priority snapshot are explicitly described when refreshed.

5. **Navigation draft loss.** A browser reproduction typed a scratch note with the clock paused, navigated to Today and returned before the 600 ms debounce. The original textarea returned empty. Scratch text, overall review and unfinished reflection editors now retain their field baseline and draft in a tab-local scope containing workspace, captured profile, contest, problem and editor kind. Input writes a synchronous session copy; navigation does not depend on an asynchronous unload save. Clean durable saves clear retention. Returning compares the preserved baseline with current storage, so competing tab changes require an explicit choice. Older unmounted save callbacks cannot replace a newer editor’s retained text, and stale workspace callbacks cannot write into a newly selected workspace. Feedback distinguishes Unsaved, Saving, Saved and Save failed without a typing live region.

6. **Active screen hierarchy.** The running contest uses a compact title and timer with quieter finish/abandon controls. Current problem selection, Open problem, personal status and scratch notes precede synchronization details. Sync state and actionable errors remain visible; detailed attribution and timing explanations use a keyboard-accessible disclosure. Existing finish and abandon confirmations remain. Light and Ink themes, Large text, long titles, reduced motion and fixed navigation are preserved.

## Remaining limits

- Hybrid coverage detection is conservative: decorative raster images also require an explicit coverage decision. OCR recovery applies to every page and uses English recognition; blurry/rotated/multicolumn content and missing positions still need source comparison.
- Uncommitted editor retention belongs to this browser tab and is separate from saved workspace records. Backups and account transport include drafts after the workspace save, not unsaved editor text. Closing the tab can discard unsaved text. If session storage is unavailable, in-memory retention protects client navigation and the editor reports unavailable reload protection.
- Contest timing still depends on the device clock; per-problem work durations remain unknown, and incomplete platform imports cannot prove no solve.
- Local cache, transport, SQL ownership and recovery fixtures do not establish live cross-device hosted-account operation. Disposable hosted-account credentials are not configured. No deployment is performed.
